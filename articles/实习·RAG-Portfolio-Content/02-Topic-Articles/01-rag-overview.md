# RAG 是怎样把外部资料带进回答的

本文整理自 RAG 课程学习记录，保留其中的解释与理解。

## 为什么需要 RAG

大语言模型的训练知识有时间边界，也未必包含企业内部资料。遇到依赖新政策、私有文档或某一业务细节的问题，如果只让模型凭已有知识回答，就可能遗漏依据，甚至把猜测说得很确定。

RAG（Retrieval-Augmented Generation，检索增强生成）的思路是：**回答前先找资料，再让模型结合找到的内容组织回答**。可以先把系统看成三部分：**知识库**保存可检索的资料，**Retriever（检索器）** 寻找与问题相关的内容，**LLM**结合问题与检索内容生成回复。这里是在生成时提供外部信息，不等于重新训练模型。

## 外部资料怎样变成可检索的知识

在用户提问之前，系统要先准备资料：读取文档，必要时把长文档切成适合查找的片段，并保留标题、出处等信息。接着为这些内容建立索引，让检索器能够通过关键词、语义相似度或两者结合找到候选片段。不同系统的索引方式可以不同，切片与向量表示也不是每种检索方式都必须使用的步骤。

这一步决定了知识库“知道什么”。如果新文件没有进入索引，或旧资料没有及时更新，后续回答也不会自动获得最新内容。若资料有访问权限限制，检索时还必须确保用户只能得到有权查看的内容。

## 用户提问后，检索与生成怎样接力

1. **检索：** 用户提出问题，检索器从已经准备好的资料中找相关文档或片段。
2. **组织上下文：** 系统把选中的片段连同用户问题交给 LLM；如果要展示出处，还需保留片段与原文档的对应关系。
3. **生成：** LLM 接收这些材料并生成回答，应用再按需要展示引用来源。回答是否忠实于材料、引用是否准确，仍需对照原文检查。

课程图把这条关系概括为“LLM + 知识库”：资料可以是模型训练时没有见过的私有、近期或特定内容；检索器把相关内容带进提问上下文，模型再据此回答。图概括的是机制，不是正确率保证。

**概念示意，并非课程执行记录或个人项目：** 假设知识库里有一份《出差报销规则》，用户问“申请交通费需要什么凭证？”系统先找到与凭证要求相关的段落，再把问题和段落一起交给模型。模型据此回答，并指出来自哪份规则；若资料没有说明某类交通费，回答就应说明依据不足，而不自行补出规定。

## RAG 能带来什么，又会在哪里出错

当资料被正确收录、能够被检索且回答确实依据检索内容时，RAG 可以帮助模型使用私有或较新的信息，也为展示出处提供条件。它有助于减少无依据的回答，但**检索到材料不等于回答一定正确**：资料可能过时或有误，检索可能漏掉关键段落，模型也可能误读已经找到的内容。

检索器还有一个直观取舍：拿得太少，可能漏掉证据；拿得太多，噪声会占用上下文并干扰回答。可以调整返回数量（Top-K）、文档切片、重排序或相关性过滤，但没有适合所有业务的固定数值。生成后的回答也要单独检查，不能只凭一次问答判断整套系统的效果。
