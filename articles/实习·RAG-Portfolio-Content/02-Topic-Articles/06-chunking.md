# RAG 文档分块：切分方法、上下文补充与策略取舍

本文整理自 RAG 课程学习记录，保留其中的解释与理解。
## Chunking：为什么不能把长文档直接塞进去

长文档如果只作为一条记录，它的向量可能把多个主题压在一起；即使被检索出来，整篇送给 LLM 也会占用大量上下文。Chunking（分块）把文档拆成更适合检索与阅读的片段。切得太大，片段不够聚焦；切得太小，回答所需的前后关系又可能丢失。因此分块方式会影响检索相关性、上下文占用和生成时能否看懂证据。

### Chunk Size 与 Chunk Overlap

**Chunk Size** 指单块允许的目标长度或上限，具体按字符还是 Token 计算要看实现。**Chunk Overlap** 指相邻块之间保留的重复内容，帮助跨边界的句子或概念继续相连。例如大小为 250 字符、重叠为 25 字符，重叠约占 10%。重叠能降低硬切导致的信息断裂，也会增加重复片段、向量数量和存储成本。

### Fixed Size Chunking：先按长度切

固定大小分块预先设定每块长度，实现简单、速度快，适合先建立基线。但第 250 个字符未必正好是句尾，可能把一个解释或表格拆开。加入适度重叠能缓解，却不能保证边界就合理。

### Recursive Character Splitting：先尝试自然边界

递归字符分割先尝试较大的分隔符；若切出的某段仍超过目标长度，再用更细的分隔符继续拆。一个便于理解的顺序是：双换行分段落、单换行分行，再考虑句子标点、词间空格，最后才按更细粒度切开。实际默认分隔符及长度计算方式由所用工具决定，中文标点、代码或 HTML 往往需要自行配置。

可以按这四步想象它的工作过程：

1. 设定 `chunk_size` 和 `chunk_overlap`。
2. 先用较高优先级分隔符切出段落。
3. 检查每段长度；较长的片段再用下一级分隔符递归切。
4. 组合成符合目标大小的块，并按需要保留相邻块的重叠。

这种方式通常比纯粹按字数硬切更尊重段落结构，预处理成本也较低。普通论文、网页资讯、产品说明文档，或希望快速建立知识库原型时，都可以先尝试它。若原文是一整段连续说明、没有可用的自然分隔符，仍可能不得不切开语义。不同资料可以使用不同边界：如拆分HTML使用段落或者标题标签来拆分；对于python代码用函数定义切分，文本文档使用换行符拆分等，都比统一按字符切更有结构意义。

### Semantic Chunking：让边界跟着话题走

语义分块想解决的问题是：文本形式上的换行和长度限制，不一定等于内容上的话题边界。它通常先把文档切成句子或短片段，再为相邻单元生成 Embedding，比较它们的语义接近程度。相近内容可以合并；差异明显时，就把这里视为候选分块边界。

可以这样理解流程：

1. 先将长文本切成适合比较的句子或短片段。
2. 为相邻句子、句组或当前块生成向量；具体比较单元取决于实现。
3. 计算相似度或不相似度，并设置断点规则。
4.计算阈值:
-  距离 <阈值：语义接近，把句子合并进当前chunk 
- 距离 >阈值：语义发生变化语义差距大，切割，新建chunk

**相似度高表示更接近；距离高表示差异更大。** 两种量的阈值方向相反，调参时需要先确认工具使用哪一个。语义分块有机会让块内内容更连贯，但检索与回答是否因此改善，要用真实文档和问题验证。

它需要额外计算 Embedding，增加预处理时间和计算资源。若使用托管模型，还可能增加 API 费用；若本地运行模型，成本则体现在本地算力。不能把所有实现都理解为“每句必有一次外部 API 调用”。

### LLM-based Chunking：让模型判断逻辑边界

还可以把文档和切分要求交给 LLM，让模型根据概念和主题变化决定边界。例如提示它尽量将同一概念留在同一块，遇到新主题再切。固定大小主要看长度，语义分块主要看向量相近程度，LLM 分块则让生成模型参与理解全文结构。

这种方式可能处理复杂叙述，但会增加模型调用、延迟和费用，切分结果也需要检查一致性。它适合在小样本上试验，再决定是否用于大规模预处理。

### Context-Aware Chunking：给已切出的块补背景

有时片段本身读得懂，脱离原文却不知道“这家公司”“上一季度”指什么。Context-Aware Chunking 在切好块后，为每块补充简短的来源背景；一种做法是让 LLM 结合整篇文档生成上下文说明，再把说明与原块一起用于检索或生成。它处理的是**块缺少背景**的问题，可以与前面的边界策略结合。

补充的背景文字可以和片段一起用于建索引，也可以在片段被找回来时交给生成模型阅读；因此它可能同时影响“找不找得到”和“找到了能否看懂”。这层作用不取决于是否只用向量检索，关键词检索也可能利用新增的文字。收益仍要评估。说明若生成错误，也可能给片段引入误导，所以需要保留原文来源并检查质量。

### 怎样选择分块方法

原型阶段可先用固定大小或递归字符分割建立低成本基线。若常出现跨边界断裂、一个块里混进多个话题，再试语义分块或 LLM 分块；若片段被检索后经常缺少上下文，则考虑补背景,Context-Aware Chunking可以应用于任何一种chunking策略，且能够提升搜索的相关性和后续内容的生成效果。用同一小批代表性文档和问题比较各方案的证据完整性、检索质量、回答质量与处理成本，通常比追逐“最先进”的分块名称更有用。
