# RAG 生成阶段：LLM 解码与采样策略

本文整理自 RAG 课程学习记录，保留其中的解释与理解。

检索到相似片段后，还要决定把哪些信息放进 Prompt、选什么模型、怎样控制输出，以及怎样判断回答是否可靠。LLM 的任务是理解当前问题和提供的资料，再生成清楚、尽量有依据的回答。

## Transformer 与逐 Token 生成

Transformer 架构可以包含 Encoder 和 Decoder。许多生成式 LLM 主要使用 Decoder；很多文本嵌入模型则使用适合编码语义的结构。这里先把注意力放在生成过程上。

用户问题进入模型后，可以按下面的直觉理解：

1. 文本被拆成 Token；每个 Token 获得一个向量表示，同时模型知道它在序列中的位置信息。
2. 注意力机制让一个 Token 结合其他 Token 的信息，判断哪些上下文与当前表示有关。模型中通常有多个注意力头，可学习不同的关系。可以用“把物体和它的描述联系起来”“辨别两个物体的空间关系”想象不同关系，但不能据此认定每个真实模型都有固定负责某项任务的注意力头。
3. 前馈网络继续处理这些表示；多个 Transformer 层反复更新 Token 表征，使模型能够结合上下文理解当前输入。层数因模型而异。
4. 模型根据已有 Token 计算下一个 Token 的概率分布，选择一个 Token 接在末尾，再重复这个过程。

可以把每层更新理解为模型逐步结合更多上下文，但“第一次猜测、第二次猜测”只是帮助理解的比喻，不是内部显式写出的解释文本。

## 采样策略：概率表里怎样选下一个 Token

模型在每一步会给候选 Token 分配分数，经过处理得到概率分布。解码策略决定从中怎样选出下一个 Token；不同设置会影响稳定性、多样性和重复程度。

![图示：采样策略：概率表里怎样选下一个 Token](图片附件/Pasted%20image%2020260901174554.png)

### Greedy Decoding：每次选概率最高的

贪婪解码每一步都选当前概率最高的 Token，不做随机抽样。它容易复现，适合希望输出稳定的场景，如某些代码补全或调试任务；也可能出现重复、表达单调的问题。每一步确定地选择最高概率，不意味着答案事实一定正确。

### Temperature：改变概率分布的“陡峭程度”

Temperature（温度）调节候选 Token 的相对概率。温度较低，分布更尖，模型更偏向高概率 Token；高于 1 时分布趋于平坦，原本不太可能选中的 Token 有更多机会。温度为 1 通常保留原始分布；很多实现把温度为 0 当作近似贪婪解码的设置，但具体行为以所用服务为准。

![图示：Temperature：改变概率分布的“陡峭程度”](图片附件/Pasted%20image%2020260901180235.png)

### Top-K 和 Top-P：先确定候选池

**Top-K** 只保留概率排名前 K 的 Token；**Top-P** 按概率从高到低累加，保留累计概率达到阈值的一组 Token，候选数量会随每一步的分布变化。两者先限制候选范围，之后仍要按解码设置从候选池中选择。

![图示：Top-K 和 Top-P：先确定候选池](图片附件/Pasted%20image%2020260901180754.png)

对照两张柱状图：Top-K 固定保留前 5 个，而图中的 Top-P 累加到至少 85% 时才停止，所以候选数会随概率分布改变。

![图示：Top-K 和 Top-P：先确定候选池](图片附件/Pasted%20image%2020260901181041.png)

### 对特定 Token 再做控制

**Repetition Penalty（重复惩罚）** 降低已经出现过的词项反复被选中的倾向，适合处理不自然重复，但惩罚过强也可能伤害正常复述。

![图示：对特定 Token 再做控制](图片附件/Pasted%20image%2020260902103311.png)

**Logit Bias（Logit 偏置）** 在概率转换前调整某些 Token 的原始分数，提高或降低它们被选中的可能性。它可以控制特定词项倾向，但由于同一个词可能对应不同 Token 序列，不能把它当成可靠的内容安全过滤器。

设置策略要服务于任务：事实性问题通常希望较稳定的输出，创意任务可以容许更多变化。温度和 Top-P 影响生成分布，却不能代替检索证据、引用检查或事实评估。
