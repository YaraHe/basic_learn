# 幻觉、引用与生成质量评估

本文整理自 RAG 课程学习记录，保留其中的解释与理解。

## RAG 仍会产生幻觉，怎样发现和缓解

知识库给模型提供了可参考的资料，也能补充模型训练中缺少的信息，但检索错误、证据不完整或生成时误读资料，都可能让回答出现无依据内容。RAG 能降低某些风险，不能消除幻觉。还可以通过以下方法来缓解RAG中的幻觉现象：

### 多次生成能否发现问题

**Self-Consistency Methods**自洽性检查对同一个问题生成多次回答，再观察事实是否互相矛盾。若关键事实反复变化，值得回查证据；但多次回答一致也可能一致地错。重复生成还会增加成本，因此它只能作为辅助信号。

### Citation Generation：让回答标出来源

Prompt 可以要求模型仅依据检索材料陈述事实，并标注来源。这有助于读者核验，但模型也可能生成看似合理却对不上原文的引用。更可靠的做法是检查“回答中的哪一句由哪份材料支持”。可以使用外部系统来处理。如：ContextCite 就是一个用于对各种内容进行评分的系统。ContextCite 研究的是模型生成内容与给定上下文的归因关系，可帮助定位哪些上下文片段可能支撑某句话；若找不到支持材料，就应进一步核查，不能把工具的归因结果直接当作事实证明。

ALCE（Automatic LLMs' Citation Evaluation）大模型引用自动评测基准专门评测**带引用 / 溯源的 RAG 问答**数据集 + 自动评测代码库，从流畅度、回答正确性、引用质量三个维度比较系统。它评的是带引用回答的表现，不等于部署了 ALCE 就能自动保证每条引用真实可靠。

下图把 ALCE 的三个观察点并列放在一起：读起来顺不顺、内容对不对、引用是否指向真正支持它的材料。前两项得分好，也不能自动推出第三项合格。
1. Fluency 流畅度：输出文本是否清晰通顺（只管文笔，不管事实对错）
2. Correctness 事实正确性：输出内容事实是否准确，检测事实幻觉 
3. Citation Quality 引用质量：引用标签与真实来源是否匹配，打击假引用、标错来源

![图示：让回答标出来源](图片附件/Pasted%20image%2020260902155751.png)

带引用回答可以分别看三件事：**流畅度**是否便于阅读，**事实正确性**是否与证据一致，**引用质量**是否把论断指向真正支持它的材料。文笔流畅不能代替事实检查，出现引用标记也不能代替引用核验。

## 评估生成环节，而不只评估检索器

评估 LLM 时要围绕它的任务：回答是否清楚、是否用到了相关资料、是否忽略噪声、事实是否有根据、引用是否准确。Ragas 是一套可用于 RAG 自动评估的工具，它会去调用**外部的 LLM（你指定的大模型）充当裁判**，按照 Ragas 内置的评估逻辑，帮你算各种 RAG 指标分数。需要自己提供用户问题、检索到的上下文 chunk、RAG 生成的回答。具体指标名称、输入字段和算法会随版本变化。

以下是评估LLM性能的指标：
### Response Relevancy：有没有回答用户的问题

Response Relevancy 关注回答与问题是否相关，不直接判断事实是否正确。

核心思想：**反向生成假想问题，向量余弦相似度打分**

测试步骤：
1. 评估LLM拿到LLM生成的答案，反向生成几条假想的用户query
2. 将假想的用户query，与用户真实原始问题，做 Embedding 向量化，计算余弦相似度
3. 把几组相似度取平均值，得到最终的 Response Relevancy 分数


### Faithfulness：论断能否从检索内容得到支持

Faithfulness 关注回答是否有证据支撑。可以先把回答拆成独立事实断言，再拿检索材料逐条判断能否支持，最后计算“受支持断言 ÷ 全部断言”。比例越高，回答越贴近给定上下文。它衡量的是相对检索材料的忠实度，不能证明材料本身就是真的。

### Context Relevance：带回来的片段与用户问题是否相关

工作步骤：
1. 输入：用户原始问题，以及检索返回的每一个 chunk 片段
2. 评估 LLM 当裁判，针对**每一段检索 chunk**做判断：这份片段里面，包含多少对解答用户问题有用的信息？
3. 输出 0‑1 之间分数。
    - 1 分：chunk 高度相关，里面有大量回答用户问题需要的信息
    - 0 分：chunk 完全无关，属于噪声垃圾片段
	最后整体会取所有检索 chunk 的平均分，作为这条样本整体的 context_relevancy 分数。

在 Ragas 的 NVIDIA Context Relevance 实现中，评估模型把用户问题与整组检索片段一起看，通过两次独立评判得到这组上下文的整体相关性分数；它不是先给每个 chunk 单独打分再汇总。分数越高，表示这组材料整体越贴近问题。

Ragas 还有噪声敏感度等指标，其他评估方案也会检查引用质量。自动裁判能扩大测试规模，也会误判，所以重要样本仍需要人工核验。除了这些单项指标，还可以收集用户点赞、点踩和文字反馈；若通过 A/B 测试比较两个生成模型，应尽量控制检索器、Prompt 等其他变量，避免把整套系统变化误归因于 LLM。
