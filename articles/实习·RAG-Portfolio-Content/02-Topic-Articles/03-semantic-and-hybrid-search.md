# 语义检索与混合检索

本文整理自 RAG 课程学习记录，保留其中的解释与理解。

## Semantic Search：词不同，意思也可能相近

语义搜索通过 Embedding 模型把查询和文档片段表示为向量，再比较它们在向量空间中的接近程度。它希望找到“措辞不同但意思相近”的内容。

<img src="图片附件/Pasted%20image%2020260826150421.png" width="504" alt="图示：Semantic Search：词不同，意思也可能相近">

嵌入模型适用于各自类型的输入数据：有的侧重词，有的面向句子或文档。输入文本被编码成向量后，可以用余弦相似度、点积或欧几里得距离等方式比较；使用哪种度量要与模型及索引设置一致。其中余弦相似度是计算用户问题向量与文档向量的夹角有多小，夹角越小语义越接近。

<img src="图片附件/Pasted%20image%2020260826150206.png" width="523" alt="图示：Semantic Search：词不同，意思也可能相近">

### 嵌入模型如何学会“接近”

可以用对比学习来理解一类嵌入模型：

1. 准备文本对或其他训练样本，把语义相关的例子视为正例，不相关的视为负例。
2. 模型先把文本映射到向量空间。起初，这些位置未必能准确表达语义关系。
3. 比较正负例在空间中的位置：希望相关文本靠近，不相关文本更容易区分。
4. 计算当前结果与训练目标的差距，反向调整模型参数。
5. 用大量样本反复训练，让向量表示逐渐适合后续的相似度检索。

具体训练数据、目标和起始模型因产品而异，不一定从完全随机的模型开始，也不一定只用一种正负样本方法。

训练完成并固定模型参数后，同一套模型会把新文本映射到可比较的向量空间。检索时要让查询向量和文档向量使用兼容的编码方式；模型也不会在每次查询时主动改变知识库中已有向量。

## Hybrid Search：把不同检索信号合在一起

关键词搜索能抓住精确词项，语义搜索能找不同措辞表达的相近含义，元数据过滤能约束日期、权限等条件。混合检索把它们组合起来，适合既要精确名词又要理解自然语言表达的问题。究竟采用哪种组合，仍应按查询类型和业务资料验证；不能预设某一种“自适应 RAG”总是效果最好。

假设关键词检索和语义检索各返回 50 份文档，可能有重复，也可能顺序不同。系统可以先或后按元数据条件过滤，再合并、去重并排序；“各 50 份”只是例子，不是固定配置。

### 倒数排名融合 RRF

RRF（Reciprocal Rank Fusion）主要使用各列表中的**名次**，不直接混合两种检索器的原始分数。某文档在多个列表都靠前，就会累积较高的融合分数。常见形式是对每个列表计算 `1 / (k + rank)`，再求和；`k` 控制靠前名次的影响程度。

![图示：倒数排名融合 RRF](图片附件/Pasted%20image%2020260827100447.png)

<img src="图片附件/Pasted%20image%2020260827101318.png" width="439" alt="图示：倒数排名融合 RRF">

有些混合检索实现还允许给关键词与语义结果不同权重，例如用 `β` 控制两路结果的比重。下图的约定是 `β = 0.8` 时语义检索占 80%，关键词检索占 20%；因此若要更重视精确词项，可降低这个图里的 `β`。这个权重是图中具体方案的设置，**不是 RRF 原论文公式必有的参数**。如果问题要求产品型号、法规编号等精确词项，可尝试提高关键词一路的权重；如果用户表达多变，可尝试提高语义一路的权重。方向仍需用样本问题验证。

![图示：倒数排名融合 RRF](图片附件/Pasted%20image%2020260827102129.png)

混合检索的可调处包括 BM25 参数、元数据过滤规则和融合权重。检索器越多，调试也越复杂；需要观察增加的召回是否真的改善最终回答。
