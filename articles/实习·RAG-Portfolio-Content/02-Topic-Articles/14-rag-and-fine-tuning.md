# RAG 与微调分别解决什么问题

本文整理自 RAG 课程学习记录，保留其中的解释与理解。

## RAG 与 Fine-Tuning 分别改变什么

RAG 在回答时提供外部资料；Fine-Tuning（微调）用训练样本调整模型参数。两者不是二选一，作用点不同。

### 监督式微调 SFT

监督式微调（Supervised Fine-Tuning，SFT）可以按三个步骤理解：

1. **准备指令样本。** 每条样本给出用户的指令或问题，以及期望模型输出的回答。
2. **比较模型输出与参考答案。** 模型按输入生成内容，训练过程计算它和期望输出之间的差距。
3. **更新参数并反复训练。** 根据差距调整模型参数，用更多样本重复这个过程，使模型逐渐适应目标任务。

指令微调是以遵循指令为目标的一类 SFT。“用户指令 + 期望输出”的样本可以教模型按指定格式、语气或步骤完成任务；以后遇到相近任务时，可能不必每次都写同样长的 Prompt 约束，效果仍取决于训练数据和评估。

微调可能改善某类任务表现，也可能影响其他任务。它常被用来调整模型**怎样回答**，例如措辞、格式和使用检索证据的习惯；能否把新知识稳定地“教进模型”，要看数据和训练方案，不能简单等同于接入一份可随时更新的知识库。

### 两种方式可以组合

RAG 适合把较新或私有的事实资料带入当前问题，微调可帮助模型更稳定地遵循任务格式或利用检索材料。可以把 RAG 提供的资料理解为当前可查的“原材料”；微调则尝试教模型怎样使用这些片段，比如优先依据证据作答，或保持指定的输出格式与话术。是否真能降低幻觉、缩短 Prompt 或节省成本，仍要通过目标任务的评估判断，不能只凭组合方式认定。

![图示：两种方式可以组合](图片附件/Pasted%20image%2020260902215024.png)

一条 RAG 原型需要理解生成模型与采样方式，选模型和组织 Prompt，检索并放入证据，检查幻觉与引用，再按复杂度决定是否增加 Agent 流程或微调。要把原型带到实际业务，还需处理质量、延迟、成本与安全等工程问题。
