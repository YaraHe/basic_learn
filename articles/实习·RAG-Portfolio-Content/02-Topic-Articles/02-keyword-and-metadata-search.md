# 关键词检索、BM25 与元数据过滤

本文整理自 RAG 课程学习记录，保留其中的解释与理解。

关键词检索回答“文本里有没有这个词”，语义检索回答“内容意思是否相近”；两者的结果可以融合排序，形成混合检索。元数据过滤则是另一类条件，用来限定文档是否符合日期、权限等要求，而不是第三种相关性评分。

## 元数据过滤：先缩小范围

元数据是与文档相关的附加信息，例如标题、作者、创建日期、所属业务和访问权限。过滤规则可以先缩小候选范围，也可以在检索后进一步筛选。例如用户只能访问自己有权限的文档，就应把权限作为明确的过滤条件；用户问“今年的政策”，日期也可能成为过滤条件。

它的优点是规则明确、速度快、便于排查，还能执行严格的匹配条件。它本身不阅读文档内容，也不判断内容与问题的相关程度，所以通常要与关键词或语义检索一起使用。实际系统中，过滤放在检索前还是检索后取决于索引和权限设计；涉及访问权限时，还必须保证最终返回的结果符合权限规则。

## Keyword Search：从词项计数到 BM25

关键词搜索首先看文档是否包含查询中的词项，再根据出现次数、词项在语料中的常见程度等信息给文档排序。它擅长精确词语匹配；若问题和文档使用不同说法，仅靠词面匹配可能找不到内容。

### 先理解词频向量和倒排索引

先用一种便于理解的**词袋式表示**：暂时不记录词语在文档中的先后顺序，只看包含了哪些词、各出现几次。这是下面词频向量的范围；实际索引也可以另外保留词的位置。

可以想象先汇总所有文档中的词语，去重后得到一张词汇表，假设共有 **X 个词**。对每份文档，按词汇表顺序留出 X 个位置：某个词出现几次，对应位置就写几；没有出现则写 0。例如第一位对应的词出现一次、第二位对应的词没出现，向量便以 `[1, 0, …]` 开头。

这样就得到一份文档的**词频向量**。一篇文档通常只用到词汇表的一小部分词，所以向量中大多数位置是 0，称为**稀疏向量**。下图用一句话的词项有无，帮助理解这些位置怎样填入。

![图示：先理解词频向量和倒排索引](图片附件/Pasted%20image%2020260826102741.png)

把多份文档的向量排在一起，可以形成“文档—词项矩阵”：每个格子记录某个词在某份文档里出现多少次。这是理解数据的直观方式。假设有 **50 万个词、100 万篇文档，矩阵就有 5000 亿个格子**；下图只画了一个很小的示意，实际系统不必把整张密集矩阵存下来。

<img src="图片附件/Pasted%20image%2020260826103231.png" width="317" alt="图示：先理解词频向量和倒排索引">

实际快速查找常使用**倒排索引**。许多词只出现在部分文档中，如果把整张矩阵原样存下，大量位置都是 0。倒排索引改以词项为入口，至少记录包含该词的文档，例如“某个词 → 文档 1、文档 3、文档 4”；为了后续评分，还可记录词频，有些实现也保留词的位置等信息。

平时是从一份文档看它有哪些词；“倒排”把方向反过来，从一个词找到包含它的文档，就像查书末的术语索引。矩阵有助于理解词频，倒排索引负责高效查找，两者不能完全画等号。下图重点看“一个词对应哪些文档”的方向。

### 最简单的评分：问题里的词出现了吗？

先不考虑复杂公式。假设问题有 5 个不同的关键词：某篇文档包含一个，就给它加 1 分，那么最高是 5 分。系统按分数排序，包含更多查询词的文档更靠前。

![图示：最简单的评分：问题里的词出现了吗？](图片附件/Pasted%20image%2020260826110847.png)

这个例子说明了关键词评分的起点，也马上暴露两个问题：同一个词出现一次和出现很多次，应不应该得一样的分？长文档词更多，会不会天然占便宜？

### 词频、长度与稀有词

**先考虑词频（TF）。** 如果某个查询词在文档里反复出现，文档可能更集中地讨论它，可以让得分随出现次数提高。但长文档更容易重复同一个词，因此还要考虑文档长度。把“关键词次数相对于全文长度的占比”作为一个直觉例子，就能理解为什么要做长度归一化；具体算法未必直接用这个除法。

**再考虑词的重要性。** 常见词 `the` 出现在许多文档中，区分能力较弱；如果 `pizza` 在当前语料中较少见，它就可能更有辨识度。逆文档频率（IDF）用语料中的文档出现情况来表达这种差别。注意：词是否稀有取决于知识库，不能只凭词本身判断。

先看 `pizza` 与 `the`：前者只出现在少数文档，后者几乎到处都有。第一张图先取出现文档的比例并倒过来，第二张图再用对数压缩过大的差距。

![图示：词频、长度与稀有词](图片附件/Pasted%20image%2020260826133058.png)

![图示：词频、长度与稀有词](图片附件/Pasted%20image%2020260826133130.png)

若稀有词权重拉得太开，可以用对数压缩差距：稀有词仍更有区分度，但不会只因为极少出现就获得夸张的权重。

![图示：词频、长度与稀有词](图片附件/Pasted%20image%2020260826133620.png)

词频和逆文档频率结合，就是 TF-IDF 的基本思路：既看词在这篇文档中出现得多不多，也看它在整个语料里常不常见。

### BM25 为什么还要处理词频

BM25 是常用的关键词相关性评分方法。它同样关注词频和词在语料中的区分度，并通过词频饱和与可调的文档长度归一化计算分数。某个词从没出现到出现几次，通常对判断相关性很有帮助；从出现十次到几十次，帮助却不应一直按同样幅度增长。BM25 用**词频饱和**处理这种边际收益递减，并用参数控制文档长度的影响。

前面的评分演变可以放在一起看。表中的“词频÷文档总词数”只是帮助理解长度处理的直觉，不是所有算法的统一公式。

| 学习层级 | 评分时增加了什么 | 想解决的问题 |
| --- | --- | --- |
| 1. 词项计数 | 查询词出现就加分；5 个不同词最多得 5 分 | 先找到包含查询词的文档 |
| 2. 词频与长度 | 考虑同一词出现次数，同时考虑文档长短 | 重复提及可能有用，但长文档不应仅凭篇幅占优 |
| 3. TF-IDF | 加入词项在整个语料中的稀有程度，并用对数控制权重差距 | 常见词与稀有词不应总是同权重 |
| 4. BM25 | 进一步控制词频收益增长，并调节长度归一化 | 词重复过多时，相关性分数不应无限线性增长 |

这是理解评分因素逐步增加的学习路径。BM25 有自己的评分形式，并非把 TF-IDF 公式简单多加一项。

**再看 BM25 与 TF-IDF 的区别：**

- 当文档某个关键词出现的次数增加时，该词对分数的贡献通常仍会增加，但每多出现一次带来的增量逐渐变小，趋向饱和。
- 课程图把一种 TF-IDF 长度处理方式画成对长文档惩罚较重，借此说明为什么要关注文档长度。但 TF-IDF 有不同的权重与归一化方式，不能概括为它总是“惩罚过于激进”；BM25 可以用 `b` 调节长度归一化的影响。

![图示：BM25 为什么还要处理词频](图片附件/Pasted%20image%2020260826141117.png)

图中“20 次出现得 1.3 倍分数”只是说明词频收益趋缓的示意，不是 BM25 在所有语料和参数下的固定比例。

BM25 中常见的两个参数是：

- **k₁**：控制词频增加时，得分增长多快以及何时趋缓。
- **b**：控制文档长度相对语料平均长度对得分的影响。

### 离线建库与在线检索

这两段工作发生在不同时间，分开看更容易理解“先建索引，再查候选”。

**离线建库（提前准备）：**

1. 处理知识库文档，统计词项出现次数，理解为给每份文档建立稀疏词频表示。
2. 建立以词项为入口的倒排索引，记录包含该词的文档和所需统计信息。这样用户尚未提问时，查找结构就准备好了。

**在线检索（用户提问时）：**

1. 将问题中的词项提取出来。例如 `pizza recipe` 会提供两个查询词。
   也可以把这些词理解为一个临时的稀疏查询表示：词汇表里与当前问题有关的位置有值，其余位置为 0。真正检索时仍主要借助倒排索引定位候选。
2. 从倒排索引找包含这些词的候选文档，不必遍历整个知识库的全文。
3. 对候选文档计算 BM25 分数，综合词频、词项权重和文档长度。
4. 按分数排序，取前 K 个结果交给后续环节；例如 Top 3 只是一个设定例子。

![图示：离线建库与在线检索](图片附件/Pasted%20image%2020260826142143.png)

BM25 提供了较成熟、可调的词项排序方法。它在许多检索系统中很实用，但是否比 TF-IDF 检索得更好、系统成本差多少，仍要结合分词、语料和实现来比较。
