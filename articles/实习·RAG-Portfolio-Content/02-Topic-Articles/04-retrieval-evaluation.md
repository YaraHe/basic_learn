# 检索质量评估：Recall、Precision、MAP 与 MRR

本文整理自 RAG 课程学习记录，保留其中的解释与理解。

## 怎样评估检索结果

先明确“相关文档”由谁标注、针对哪一批问题，才能解释检索指标。

- **Recall（召回率）**＝检索到的相关文档数 ÷ 知识库中该问题的全部相关文档数。它回答“有没有漏掉有用资料”。
- **Precision（精确率）**＝检索到的相关文档数 ÷ 检索到的文档总数。它回答“拿回来的资料有多少真的有用”。

返回更多文档，召回可能提高，噪声也可能增加。因而常看 Precision@K、Recall@K，只检查前 K 个结果；K 应贴近实际会传给生成模型的数量。

### AP 与 MAP：相关结果排得靠前吗？

只知道前 K 条有几条相关还不够。如果相关结果都在列表末尾，实际使用感受仍可能不好。**AP（Average Precision）**对一条查询，在每个相关结果出现的位置计算当时的 Precision@K，再取平均。这里采用的经典定义以该查询**已知的全部相关文档数**为分母；没被检索到的相关文档仍计入分母，其对应的 Precision 贡献记为 0。例子中若一共有 3 个相关文档，即使只找回 2 个，分母仍是 3。

**MAP（Mean Average Precision）**再把**多条查询的 AP 取平均**，衡量整套检索器在测试问题上的排序表现。

### RR 与 MRR：第一篇有用文档在哪

**Reciprocal Rank（RR，倒数排名）**只看第一篇相关文档的位置：第一名出现得 1 分，第二名得 1/2，越靠后分数越低。

![图示：RR 与 MRR：第一篇有用文档在哪](图片附件/Pasted%20image%2020260827125729.png)

图里第一篇有用文档从第 1 名落到第 2、4 名时，RR 依次从 1 降到 1/2、1/4；下一张图把这个直觉推广到多条问题的平均值。

![图示：RR 与 MRR：第一篇有用文档在哪](图片附件/Pasted%20image%2020260827125757.png)

对多条测试问题的 RR 求平均，就是 **MRR（Mean Reciprocal Rank，平均倒数排名）**。它适合判断系统能否很快把至少一篇有用文档放到前面。

![图示：RR 与 MRR：第一篇有用文档在哪](图片附件/Pasted%20image%2020260828125250.png)

综合看，Recall 先回答检索器有没有找全相关资料，这是后续生成有证据可用的基础；Precision 关注带回多少噪声，MAP 关注多条问题的整体排序，MRR 关注第一篇相关结果出现得有多早。不能只看一个指标：如果漏掉关键资料，即使排在前面的文档看起来不错，回答也可能不完整。具体指标仍要与产品目标对应。
