# 话轮检测与打断：语音 Agent 何时说、何时停



语音 Agent 不仅要识别用户说了什么，还要决定何时回答、用户插话时如何停下。这里以上游语音转写、下游生成与播放已经连通为前提，沿着课程图看话轮、打断和对话上下文。

## 何时回答，以及如何处理打断

人类聊天会交替说话，也就是话轮交替。**Turn Detection 就是语音 Agent 用来判断：用户什么时候说完了，Agent 才可以开口回复**。 它同时依靠两路信号联合判断：

1. **音频信号**：VAD 检测有没有人在说话。
2. **文本信号**：语义话轮检测判断转写内容是否像一句已经说完的话。其他系统也可能采用不同配置。

![课程图：Pasted image 20260910205531.png](图片附件/Pasted%20image%2020260910205531.png)

1. **VAD**
   - 输入是用户音频；课程用小型分类模型识别语音活动。
   - 它判断当前是否有人说话，不理解句子语义。
   - 从说话转为静音时开始计时；计时期间再次说话就重置计时器。
   -  缺点：只听声音，分不清「用户说完」还是「思考停顿」，容易误触发，造成AI抢话。因此短暂停顿可能被误认作结束，让 AI 抢话。
2. **语义话轮检测**
   - 输入是 STT 转写与对话上下文；课程图以模型判断语义完整度。
   - 理解句子语义，判断用户语句在语义上是否已经说完。
   - 逻辑：如果识别到用户只是中间停顿，语义还不完整，就延迟VAD的计时器，阻止AI提前开口。

**两路合并后的链路**：用户音频同时交给 VAD 与 STT；① 送入VAD做音频静音检测；② 送入STT转为文字，文字送入语义话轮检测。。话轮检测综合两个结果，在满足条件时发出 `end of turn` 事件，再让 Agent 进入回答阶段。这是课程讲解的实现流程，阈值与信号来源可按产品需求配置。

当话轮检测Turn detection发出结束信号，系统才把本轮识别结果交给 LLM 生成回复。图中逐步补入语音检测与文本判断，是前一张基础架构图的延伸。

VAD 还可能参与另一件事：当 AI 正在说话时，识别用户是否开始讲话。

**场景**：AI 回答冗余、用户改变想法或要自我纠错，于是用户中途开口，打断Agent回复。

这里两个判断方向不同：
- 话轮检测：用户停下来后，话轮检测要决定是否说完；
- 打断识别： AI 正在发声时，检测到用户语音，系统要判断是否构成真正的打断。短促应和声或误检不一定要打断。

在本课程的打断流程中，系统需要停止当前播放，并处理仍在生成或等待播放的内容，让 Agent 从发言转入聆听。具体哪些生成任务会被取消，取决于框架、设置和任务性质，不能一概认为整条下游管道都被清空。

![课程图：Pasted image 20260910213449.png](图片附件/Pasted%20image%2020260910213449.png)

**上下文也要跟着用户真正听见的内容走。**
通常传给 LLM 的对话上下文会包含最新用户转写、此前用户和 Agent 的对话；如果用了工具，也可能包含工具调用与结果。是否启用工具由任务决定，不是所有生产级语音 Agent 的必备条件。

当用户打断时，已生成的文字可能尚未播放。课程描述的 LiveKit 会把上下文裁剪到用户实际听到的那部分语音，使下一轮不会误以为用户听过尚未播出的回答；剔除AI已经生成、但是还没播放给用户听见的内容，避免对话历史错乱。这属于该框架的具体处理机制。
