# Agentic AI：自主性、任务分解与工作流模式



## 自主性程度与应用

Agent 并非只有“完全自主执行”一种形态。即使自主性较低，只在预设流程中的某些环节让模型作判断，也可能带来实际价值。许多企业开发的应用正处于这类不同程度的自主性之间。先确定哪些步骤可交给模型、哪些仍由程序或人把关，比一开始追求最高自主性更重要。

![课程图：Agent 自主性程度](图片附件/Pasted%20image%2020260814155135.png)

什么任务适合 Agentic AI？

如果步骤清晰、已有标准操作流程，而且只处理文本，实现通常较容易；如果步骤事先不明确，需要边规划边解决，或同时处理声音、图像等多模态材料，难度就会增加。这个对比帮助判断任务与可用能力是否匹配，并非说复杂任务不能做。

## 如何拆出真正可执行的步骤

构建 Agent 工作流时，一个关键技能是分析业务任务，找出能独立完成的步骤。拆出步骤还不够，需要逐步追问：**这一步能否由 LLM、少量程序代码或现有工具函数完成？** 如果答案是否定的，说明这一步可能仍太笼统，要继续拆分。比如“完成一份研究报告”并不是一个直接可执行的动作；搜索资料、筛选来源、阅读内容、撰写初稿才更接近可执行步骤。

当输出不理想时，还可以反过来问：如果由人处理，他会先检查什么、补充什么信息、再做什么？这种对人的工作过程的观察，能帮助识别遗漏的步骤和反馈环节，而不是只改写最后一句提示词。

判断步骤能否执行，还要盘点手头有哪些“积木”：LLM 可用于文本生成、信息提取和提出工具请求；其他模型可做 PDF 转文本、语音或图像处理；API 能提供搜索、实时数据或其他外部操作；信息检索与代码执行也能成为工作流的一部分。先看能力清单，再决定哪一步交给哪种能力，能避免把所有步骤都笼统地交给 LLM。

## 先认识评估与四种设计模式

工作流搭出来之后，不能只看少数几次输出“感觉不错”。这些方法为后续改进提供依据：

- 可以用代码追踪特定错误出现的频率，例如结果是否提到了不该提的竞争对手；
- 对于自由文本等难以直接写规则评分的结果，可以让 LLM 按明确标准辅助评审。
- 还要区分**端到端评估**（看最终结果）和**组件级评估**（看某个步骤），并通过错误分析检查中间输出，找到没有达到预期的环节。

课程介绍了四种常见的工作流设计模式：

1. **Reflection（反思）**：让同一个或另一个模型审查初稿，提出修改意见，再迭代输出。每个智能体都被提示扮演某种角色的LLM(Coder Agent+Critic Agent)，反复交流迭代更好的结果.
2. **Tool use（工具使用）**：模型判断是否需要工具，并提出调用请求；工具提供外部信息或执行某项动作。
3. **Planning（规划）**：模型先决定行动步骤及其顺序，再按计划执行。
4. **Multi-agent collaboration（多 Agent 协作）**：让不同角色分担子任务，按某种通信关系共同完成工作。

这四种模式可以组合，也不意味着每个应用都必须使用全部模式。

课程还列出可供工具使用模式调用的能力类别：分析和代码执行、网页或数据库的信息获取、邮件与日历等生产力工具，以及图像生成、描述、OCR。选工具仍应从具体任务出发，而不是因为某类工具存在就全部接入。

## 学习线索与范围

这份课程笔记的主线可以连起来看：先把任务拆成可执行步骤；为需要判断或外部信息的步骤安排模型与工具；用反思、规划或多 Agent 协作组织流程；再通过评估、错误分析和组件测试找到真正值得改进的地方，最后检查速度与成本。不同模式是可选的设计办法，实际使用要看任务、工具与评估结果。
