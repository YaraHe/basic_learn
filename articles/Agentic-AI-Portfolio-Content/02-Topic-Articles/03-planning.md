# Planning：从结构化计划到代码执行

本节宏观的介绍了规划流程，主要是针对用户问题，列出步骤清单，然后让LLM逐步执行计划中的每一步．第二节将深入探讨这些计划的具体结构和细节,以及如何将这些内容串联起来,让LLM规划并执行任务.

## 先形成计划，再逐步执行

规划模式让模型面对用户问题时，先列出准备采取的行动及顺序，再让系统逐步执行。与预先写死的固定流程相比，模型可以根据当前目标选择步骤；但计划也需要明确工具、参数和每一步的结果如何交给下一步，不能只写成空泛的待办清单。

![课程图：客服 Agent 按计划依次调用商品工具](图片附件/Pasted%20image%2020260818115348.png)

课程展示了一种把计划写成 JSON 的方式，如下图左侧“plan"。客服 Agent 的示例中，用户问“有没有低于 100 美元的圆形太阳镜库存”。模型得到可用工具描述后，先用 `get_item_descriptions` 寻找圆形太阳镜，再把结果交给 `check_inventory` 检查是否有货，最后用 `get_item_price` 判断有货商品是否低于 100 美元。下图左侧的 JSON 截图展示前两步的结构化写法：步骤编号、描述、工具名和参数，并让第二步引用第一步结果。下游程序解析计划后才能逐步执行；后一步如何取得前一步输出，是需要明确的数据流。这是课程中的一种实现方式，不表示所有 Agent 都必须输出 JSON。

![课程图：JSON 计划、工具和步骤间输入](图片附件/Pasted%20image%2020260818120301.png)

## 用代码表达计划

如果已有工具集合难以覆盖较宽泛的任务，课程提出另一种规划思路：让模型直接编写能串起多个步骤的代码，再由系统执行，而不是先输出 JSON 计划、逐项调用工具。代码本身就表达了读取、转换、筛选、计算和输出的顺序。

课程给出两个与交易记录有关的例子。第一个问题是“最近五笔交易各是多少金额”：模型生成的代码读取 `transactions.csv`，把日期列转为日期类型，按日期从新到旧排序，取前五行，再输出金额列。第二个问题是“过去一周有多少笔不重复的交易”：代码读取 CSV 并解析日期，构造过去一周的时间范围，筛选日期落入范围的行，去重后计数。两张截图采用了课程约定的 `<execute_python>` 标签来标示待执行代码；标签本身并不会执行代码，仍需有程序识别、执行并返回结果。

![课程图：用代码求最近五笔交易金额](图片附件/Pasted%20image%2020260818121737.png)

![课程图：用代码统计过去一周的不重复交易](图片附件/Pasted%20image%2020260818121709.png)

这种方式能灵活组合操作，但代码能否运行、数据字段是否与示例一致、执行权限是否受控，都需要由承载程序处理。课程也提醒要考虑隔离的执行环境。
